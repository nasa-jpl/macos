# MACOS Manual Project

Reproducible pipeline that transforms `macosMan3_2_styled.docx` into
`macosMan4_0_styled.docx` by applying numbered patch scripts.  Each
patch is small (~50 lines), uses shared helpers in
`scripts/docx_helpers.py`, and is re-runnable from a fresh unpack of
the source.

## Why this exists

The original FrameMaker source is gone.  Adobe Acrobat's PDF→DOCX
converter produced `macosMan3.2.docx` with no semantic styles —
pandoc round-trips destroyed formatting.  A separate Claude AI
session restructured the Acrobat output into
`macosMan3_2_styled.docx`, which has clean paragraph styles
(BodyText, CodeBlock, ListParagraph, Heading1..4, FigureCaption).
That styled file is now the canonical input; we patch it via XML
transforms instead of cutting and pasting in Word.

## Cycle

```bash
python patches/run_all.py
# regenerates macosMan4_0_styled.docx from scratch
```

Internally:
1. `scripts/unpack.py` extracts `macosMan3_2_styled.docx` into `working/`.
2. Each numbered patch parses `working/word/document.xml`, mutates the
   tree, and saves it back.
3. `scripts/pack.py` zips `working/` into the output `.docx`.

Re-runnable: fresh unpack each time, so partial results from a previous
run never leak in.

## Adding a new patch

```bash
cp scripts/transform_template.py patches/NN_my_change.py
# edit patches/NN_my_change.py — fill in the transform() function
```

Add the new file to `PATCHES = [...]` in `patches/run_all.py`.  Patches
run in numeric order; pick a number that places the patch in a sensible
neighborhood (10–19 cover §1, 20–29 cover §3, 30–39 cover §4, 40–49
cover §5, 50–59 cover §7, 60–69 cover §9, 90+ for appendices).

A patch should:
- Anchor on a stable feature of the source — usually a heading text or
  paragraph style — never on absolute paragraph indices.
- Use `find_para_by_text(...)`, `iter_paragraphs(root)` with style/text
  filters, or the `find_para_parent(...)` + `list(parent).index(...)`
  pattern to locate insertion points.
- Build new content with `make_para(style, text)` from
  `docx_helpers.py`.  Style names must match those already present in
  the styled document (see the README inventory).
- Return a stats dict for the patch_base apply() runner to print.

## Single source of truth: Appendix C

`patches/90_appendix_c.py` reads `macos_f90/macos_help.inc` directly
and rebuilds Appendix C from the live HELP output.  When new commands
are added in `macos_cmd_loop.inc` and a corresponding line is added to
`macos_help.inc`, simply re-run `run_all.py` and the appendix updates.
Never hand-edit Appendix C in the docx.

## Don't commit

- `working/` — unpacked XML, regenerated by every run.  Already in
  `.gitignore` via `docs/macos-manual/working/`.
- `scripts/__pycache__/` — Python bytecode; gitignored too.

## What's outside this project

- `docs/macosMan3.2.pdf` — original v3.2 PDF.  Reference only.
- `docs/macosMan3.2.docx` — Acrobat's bare-bones conversion of the
  PDF, kept for archival; do not patch this directly.
- `docs/Archive/macosMan4_pandoc.doc` — earlier pandoc round-trip
  attempt; formatting destroyed, kept as a cautionary reference.
  Gitignored.

## Known issues from the source styling pass

(Inherited from the Claude AI restructuring; document, don't fix here):

- 73 Symbol-font paragraphs (math equations) need LibreOffice's
  equation editor to be re-rendered.  Find with:
  `python scripts/inspect.py sample Normal` — look for `font='Symbol'`.
- 7 large-font diagram fragments orphaned from FrameMaker figures.
- ~1274 remaining `Normal` paragraphs (TOC remnants, diagram labels)
  that could use further classification.

These don't affect the patch chain — they're scoped to the styled
input and will carry through to the output unchanged.
