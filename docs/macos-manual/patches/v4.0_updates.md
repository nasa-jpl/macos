# MACOS Manual v3.2 → v4.00 Update Patches

This document gives the text to insert / replace in `macosMan3.2.docx`
to bring it up to MACOS v4.00.  Each section below is a self-contained
patch with a target location in the manual and the new content.

The original `.docx` was Acrobat-converted from a FrameMaker PDF, so
the cleanest workflow is:

1. Open `macosMan3.2.docx` in Word
2. For each patch, locate the target heading and either replace the
   existing text (REPLACE patches) or insert new content (NEW patches)
3. Save as `macosMan4.0.docx`
4. Update the cover-page version number "3.2" → "4.00"

The patches are grouped by which v4.00 feature they document:

## A. Cover page and "New Features" overview

### A1. REPLACE Section 1.3 heading and body

**Locate**: `1.3 New Features of Version 3.2`

**Replace heading with**: `1.3 New Features of Version 4.00`

**Replace the body with**:

> MACOS 4.00 (April 2026) is a feature release built on the
> Fortran 90 / SMACOS infrastructure introduced in v3.2.  It adds a
> new general-purpose composite surface (FreeForm), modernizes the
> graphics layer, expands the SMACOS / GMI MATLAB interface, and
> adds new utility commands and a separate segmented-mirror
> prescription generator.
>
> A summary of changes since MACOS 3.2:
>
> - **FreeForm composite surface (`SrfType = 14`).**  Single surface
>   type combining a conic base with a Cartesian monomial sag
>   ("Mon"), a free-form Zernike sag ("FF"), and an interpolated
>   grid sag, all on independent coordinate frames.  Replaces the
>   ad-hoc combination of MonGrData / Interpolated / Aspheric
>   surfaces previously needed for non-axisymmetric, gridded, and
>   fitted optics.  See §4.5.11.
>
> - **Per-segment Zernike inputs.**  In addition to the existing
>   monomial-form `MonCoef`, MACOS now reads sparse Zernike form
>   `MonZernCoef` / `MonZernModes` and `FFZernCoef` / `FFZernModes`
>   directly in `.in` files.  Conversion to monomial form happens
>   internally at trace time (BornWolf, ANSI, Fringe, Noll,
>   AnnularNoll, Hex, ExtFringe orderings supported).  See §4.5.4.
>
> - **Per-ray status tracking.**  Every ray now records why it
>   failed (miss, obscured, root-find bracket failure, max-iter
>   failure) and which element it failed at.  The end-of-trace WARN
>   summary breaks down failures by category and throttles
>   bracket/iter messages after the first 20.  No more silent NaN
>   propagation through downstream surfaces.
>
> - **Graphics modernization.**  Built-in giza graphics backend
>   replacing legacy PGPLOT (PGPLOT still selectable at build
>   time).  New IMGMODE command toggles between astronomical
>   (negative, large→dark) and conventional (positive, large→light)
>   display polarity.  Colorbar wedge labels reflect the active
>   STRETCH (LIN / LOG / SQRT).  See §6.x.
>
> - **SEGRAYTRACE command.**  Trace a single ray through the
>   geometric center of a chosen segment element and print the ray
>   state at every downstream surface.  Useful for verifying
>   segmented-mirror prescriptions.  See §5.2.
>
> - **SegMirMaker external tool.**  Standalone utility, in
>   `MACOS_resources/segmirmaker/`, that generates segmented-mirror
>   `.presc` and `Hx.m` files.  Replaces the SMPGe (1992) generator
>   and adds support for FreeForm parents.  See §4.4.11.
>
> - **GMI MATLAB interface upgrades.**  New 14th MEX argument
>   `pmonzern` for FreeForm MonZernCoef perturbations (parallel to
>   the existing `pzern`).  New `param.monzernSrf` element list.
>   Nominal-state save/restore extended to cover FreeForm
>   coordinate frames (`pFF/xFF/yFF/zFF`, `pData/xData/yData/zData`)
>   so per-element rigid-body perturbations no longer leak across
>   GMI calls.  See §9.
>
> - **Graceful Ctrl-C.**  SIGINT installs a clean-exit handler at
>   start-up; pressing Ctrl-C at the `MACOS>` prompt (or during a
>   long trace) prints `MACOS: interrupted` and exits cleanly,
>   replacing the Intel runtime's `forrtl: severe (69)` traceback.
>
> - **HELP command rebuilt.**  All ~140 dispatched commands are now
>   listed (vs. ~75 in v3.2), grouped into 15 categories with one-
>   line effect descriptions and prerequisite tags
>   (`[Rx]` / `[BLD]` / `[DIFF]`).  See §3.2 and Appendix C.

## C. IMGMODE / display polarity / stretch-aware labels

### C1. NEW Section 6.x.x "Image polarity and stretch"

Insert as a new sub-section under §7 (Wavefront and Image Plots) just
before §7.3 "Plot Type Commands":

> **Image polarity (IMGMODE).**  Image-type plots (INTensity,
> PIXillated, OPD-as-image) can be rendered in either of two
> polarities:
>
> - **Astronomical** (default, "ASTRO" or "NEG"): large pixel
>   values render dark, small values render bright.  Matches the
>   PGPlot convention many MACOS users are accustomed to.
> - **Conventional** ("CONV" or "POS"): large values bright, small
>   values dark.  Matches general scientific imaging.
>
> Toggle with the `IMGMODE` command:
>
>     MACOS> IMGMODE
>     Enter image polarity (NEG/POS, ASTRO/CONV): [NEG]: CONV
>
> The setting persists for the session; it does not affect the
> non-image plot types (CONTOUR, SLICE, WIRE, SPOTDIAG, PLOTCOL),
> which always render with black ink on white.
>
> **Stretch-aware colorbar labels.**  When `STRETCH` is active
> (LOG10 or SQRT), the colorbar wedge label reflects the active
> stretch.  Examples:
>
> - INT plot, STRETCH=LIN: `Intensity`
> - INT plot, STRETCH=LOG10: `LOG10 Intensity`
> - INT plot, STRETCH=SQRT: `SQRT Intensity`
> - PIX plot, STRETCH=LOG10: `LOG10 Pixel value`
> - OPD with `BaseUnits`: `OPD (mm)` etc.
>
> The label is set by the command handler before the draw routine
> emits it, so the polarity/stretch and the label always match.

## D. Ctrl-C and blank-command behaviors

### D1. NEW Section 3.4.x "Interrupting MACOS"

Insert as a new sub-section under §3.4 "Entering Commands":

> **Ctrl-C interrupts cleanly.**  Pressing Ctrl-C at the
> `MACOS>` prompt — or during a long trace, build, or propagation —
> prints `MACOS: interrupted` and exits with status 0.  No more
> Intel-runtime "forrtl: severe (69)" traceback.
>
> Internally MACOS installs a SIGINT handler at startup
> (`install_sigint_handler`, called from `macos.F` before any Fortran
> runtime initialization).  The handler uses `_exit(0)` so it is
> async-signal-safe and fires regardless of what the runtime is
> doing.

### D2. UPDATE Section 3.4 last paragraph

After the existing description of how commands are entered, append:

> **Empty input is ignored.**  Pressing return at the `MACOS>`
> prompt with no command is a no-op — useful for scrolling the
> history or clearing the input buffer without re-running the last
> command.
>
> **Unknown commands** print a single-line warning rather than the
> verbose multi-line traceback that v3.2 produced.

## E. FreeForm composite surface (SrfType = 14)

### E1. NEW Section 4.5.11 "FreeForm Surfaces"

Insert as a new sub-section after §4.5.10 "Interpolated Surfaces
Using X-Y-Z Data":

> **4.5.11 FreeForm Surfaces**
>
> A FreeForm surface is a single MACOS surface type
> (`SrfType=14`, `Surface=FreeForm`) that combines up to four
> independent contributions to the surface sag:
>
>     z(rho) = z_conic(rho) + z_Mon(rho) + z_FF(rho) + z_grid(rho)
>
> where:
>
> - **z_conic** is the underlying conic of revolution defined by
>   `KrElt`, `KcElt`, and the optical axis `psiElt` through the
>   vertex `VptElt`.
> - **z_Mon** is a Cartesian-monomial sag in the segment-local
>   coordinate frame `(pMon, xMon, yMon, zMon)`, normalized by
>   aperture `lMon`, with coefficients `MonCoef` (or
>   `MonZernCoef` in Zernike form).  Sentinel: contribution is
>   active only when `lMon > 0`.
> - **z_FF** is a free-form Zernike sag in an independent
>   coordinate frame `(pFF, xFF, yFF, zFF)`, normalized by `lFF`,
>   with coefficients `FFCoef` (or `FFZernCoef` in Zernike form).
>   Sentinel: contribution is active only when `lFF > 0`.
> - **z_grid** is an interpolated sag from a regularly-gridded data
>   array, on an independent coordinate frame `(pData, xData,
>   yData, zData)` with grid spacing `GridSrfdx`.  Sentinel: active
>   only when `nGridMat > 0`.
>
> The Mon, FF, and grid contributions can be enabled in any
> combination.  Setting the corresponding sentinel to zero (or
> omitting it from the prescription) disables that term.
>
> **Why three independent frames.**  In segmented mirrors generated
> by SegMirMaker (§4.4.11), the FF coefficients describe the parent
> surface and the FF frame is parent-aligned (so all segments share
> the same FF Zernike set), while the Mon frame is per-segment
> (face-aligned) so each segment can carry its own figure error
> later via MonZernCoef.  The grid frame is parent-aligned so the
> data array represents a global perturbation map.
>
> **Independence is enforced in the surface evaluation.**
> `FreeFormSrf` (in `surfsub.F`) treats the Mon, FF, and grid sags
> as displacements along their own z-axes
> (`zMon`, `zFF`, `zData`).  Earlier MACOS versions assumed all
> three shared a single z-axis, which produced incorrect
> intersections when, for example, the segment Mon frame was
> face-aligned with `zMon = -psi` while `zFF = +psi` (a 180°
> mismatch in z direction).  See §4.4.11 for context.
>
> **Example.**  Conic + Mon + FF + grid:
>
>     iElt=    1
>  EltName= primary
>  Element= Reflector
>  Surface= FreeForm
>    KrElt= -1.000D+02
>    KcElt= -1.0
>   psiElt=  0  0  1
>   VptElt=  0  0  0
>   RptElt=  0  0  0
>     lMon=  50.0
>     pMon=  0  0  0
>     xMon=  1  0  0
>     yMon=  0  1  0
>     zMon=  0  0  1
>  MonZernType= BornWolf
>  nMonZernCoef= 16
>  MonZernModes=  1  3  4  5  9 10 11 12 13 19 20 21 22 23 24 25
>  MonZernCoef=  1.197E+0  ...
>      lFF=  100.0
>      pFF=  0  0  0
>      xFF=  1  0  0
>      yFF=  0  1  0
>      zFF=  0  0  1
>  FFZernType= BornWolf
>  nFFZernCoef= 16
>  FFZernModes=  ...
>  FFZernCoef=  ...
>  nGridMat= 256
>  GridFile= flat.txt
>  GridSrfdx= 31.25
>     pData= 0  0  0
>     xData= 1  0  0
>     yData= 0  1  0
>     zData= 0  0  1

## F. Per-segment MonZernCoef and FFZernCoef inputs

### F1. NEW Section 4.5.4.x "Sparse Zernike input"

Insert as a sub-section under §4.5.4 "Zernike Surfaces":

> **Sparse Zernike input.**  In addition to the dense `MonCoef`
> form (120 coefficients in Cartesian monomial order), MACOS reads
> Zernike coefficients in a sparse "modes + coefs" form:
>
>     MonZernType= BornWolf
>     nMonZernCoef= 4
>     MonZernModes= 4  9  16  25
>     MonZernCoef= -4.819E+00  4.001E+00  1.197E+00  2.269E-03
>
> `MonZernType` selects the Zernike ordering and normalization:
>
> | Type            | Ordering / normalization                   |
> |-----------------|--------------------------------------------|
> | `ANSI`          | ANSI Z80.28 ordering, unnormalized         |
> | `BornWolf`      | Born&Wolf ordering, unnormalized           |
> | `Fringe`        | Fringe ordering, unnormalized              |
> | `NormANSI`      | ANSI Z80.28, RMS-normalized                |
> | `NormBornWolf`  | Born&Wolf, RMS-normalized                  |
> | `NormFringe`    | Fringe, RMS-normalized                     |
> | `NormNoll`      | Noll ordering, RMS-normalized              |
> | `Noll`          | Noll ordering, unnormalized                |
> | `NormAnnularNoll` | Noll, RMS-normalized for annular pupil   |
> | `NormHex`       | Hex Zernikes (Mahajan), RMS-normalized     |
> | `ExtFringe`     | Extended Fringe ordering, unnormalized     |
>
> Conversion to the internal monomial form (`MonCoef`) happens
> automatically at trace time.  The same scheme applies to FF
> Zernikes: `FFZernType`, `nFFZernCoef`, `FFZernModes`,
> `FFZernCoef`.
>
> Modes are 1-indexed.  `MonZernModes(k) = 0` is reserved as a
> sentinel meaning "no mode k in this set".  The sparse form is
> equivalent to a dense `MonCoef` array with most entries zero;
> use the form that's more compact for your case.

## G. Per-ray status tracking

### G1. NEW Section 5.2.x "Ray status reporting"

Insert as a sub-section under §5.2 "Ray-Trace Commands", just after
§5.2.3 "Undefined Rays":

> **5.2.3a Per-ray status.**  Every ray in a trace now carries a
> recorded status:
>
> - `OK` (0) — ray successfully terminated at last requested
>   element
> - `Obscured` (1) — ray was blocked by an obscuration or aperture
> - `Miss` (2) — ray missed a surface (no intersection found)
> - `Bracket` (3) — root-finding bracket failure on a composite
>   (FreeForm / aspheric / grid) surface
> - `MaxIter` (4) — root-finder hit its iteration limit
> - `Undef` (5) — initial state, never updated (should not happen
>   in a normal trace)
>
> The end-of-trace WARN summary breaks down failures by category
> rather than just printing a count.  Bracket / iter messages are
> throttled after the first 20 to keep the terminal usable when
> many rays fail.
>
> The first failure for each ray is recorded with the offending
> element index and a short description; subsequent failures on
> the same ray are not overwritten so the root cause is preserved.

## H. SEGRAYTRACE command

### H1. NEW Section 5.2.x "SEGRAYTRACE"

Insert as a new sub-section under §5.2 "Ray-Trace Commands", after
§5.2.4 "RAY":

> **5.2.4a SEGRAYTRACE**
>
> Trace a single ray that passes through the geometric center of
> a chosen segment element (its `RptElt`), printing the ray state
> at every downstream surface.  Useful for verifying that
> segmented-mirror prescriptions place segments where you expect.
>
>     MACOS> SEGRAYTRACE
>     Enter segment number (0=quit): [0]: 5
>     Ray  1 segment from Element 0 (InputRay   ) to Element 5 (Seg5):
>        Starting point=  ...
>        End point     =  ...   (should be RptElt(:,5))
>        Direction     =  ...
>     ...
>     Enter segment number (0=quit): [0]: 0
>     MACOS>
>
> The source ray's position is automatically offset from `ChfRayPos`
> so the resulting ray (parallel to `ChfRayDir` for a collimated
> source, or aimed from `ChfRayPos` for a point source) lands
> exactly on the segment's recorded `RptElt`.  The segment-dispatch
> path is forced to fire only on the chosen segment via
> `RayToSegMap`; other segments are skipped.
>
> The trace endpoint at the segment's element should match
> `RptElt` to within `SFFZPSolve`'s tolerance (~10⁻¹¹ mm).
> Larger mismatches diagnose generator bugs:
>
> - **~180° rotational mismatch** (e.g. Seg2's endpoint matches
>   Seg5's RptElt): the segment-numbering psi-flip in the
>   generator didn't fire when it should have.
> - **~mm radial mismatch** in the surface-normal direction: the
>   generator computed `RptElt` on the conic only, missing the FF
>   Zernike sag.
>
> The command requires an Rx loaded with at least one Segment
> element; otherwise it prints "Element N is not a Segment" and
> re-prompts.

## I. SegMirMaker external tool

### I1. UPDATE Section 4.4.11 "Hex and Pie Segmented Mirrors"

Append after the existing body:

> **Generating segmented prescriptions: SegMirMaker.**
> Hand-editing a `.in` file to define every segment of a 7- or 19-
> segment mirror is tedious.  MACOS v4.00 ships with a separate
> tool, `SegMirMaker`, in `MACOS_resources/segmirmaker/`, that
> generates a `.presc` (suitable for inclusion in a `.in` file) and
> an `Hx.m` edge-sensor measurement matrix from a parent
> prescription.
>
> SegMirMaker accepts:
>
> - A MACOS `.in` parent prescription.  The parent element can be
>   any conic or FreeForm surface.
> - The number of rings (`nRing = 1` for 7-segment, `2` for 19-
>   segment, …).
> - The axis orientation `psi`, segment size or aperture diameter,
>   inter-segment gap, and segment standoff for the segmentation
>   plane.
> - Either 3-DOF (piston/tip/tilt) or 6-DOF segments.
>
> For FreeForm parents, SegMirMaker copies the parent's `lFF`,
> `FFCoef`, FF coordinate frame, grid data, and grid frame verbatim
> into every segment, so all segments share the parent's underlying
> FreeForm shape.  Each segment's Mon slot is left empty
> (`MonZernCoef = 0`) but with `lMon = L2` (half the segment
> width); the user can later add per-segment figure error via the
> Mon Zernike coefficients without re-running SegMirMaker.
>
> SegMirMaker is the modernized successor to the SMPGe
> ("Segmented Mirror Prescription Generator") VAX Fortran tool
> from 1992; the original is preserved in
> `MACOS_resources/segmirmaker/Archive/SMPGe.for`.
>
> See `MACOS_resources/segmirmaker/README.md` for full usage.

## J. GMI MATLAB interface upgrades

### J1. UPDATE Section 9 "MACOS as a Subroutine (SMACOS)"

Add a new sub-section at the end of §9:

> **9.x GMI: MATLAB MEX interface**
>
> GMI (`MACOS_resources/GMI/`) is a thin MATLAB MEX wrapper around
> SMACOS, packaging perturbations and pulling back OPD / PIX /
> SPOT / complex-EF arrays into MATLAB.  V4.00 changes:
>
> - **NRHS = 14** (was 13).  Old `call_GMI.m` callers passing 13
>   arguments will fail with `'GMI requires 14 input arguments'`.
>   The new 14th argument is `pmonzern`, a MonZernCoef perturbation
>   vector parallel to the existing `pzern` for FreeForm surfaces.
> - **`param.monzernSrf`** — column vector of FreeForm element
>   indices to perturb (analogous to `param.zernSrf`).  Encoded in
>   `pflg` with a 9999 sentinel when absent.
> - **`param.pmonzern`** — per-mode coefficient vector, length
>   `length(monzernSrf) * nmonzern`, where `nmonzern` defaults to
>   `param.mzern`.  Read inside `call_GMI.m` and forwarded as the
>   14th MEX argument; user code does not call `GMI()` directly.
> - **GMI.inc compile-time sizes**: `numseg = 7`, `mzern = 15`
>   (up from 6 / 12) to support 7-segment FreeForm test cases with
>   15 modes per segment.  When a runtime `param.mzern` exceeds the
>   compile-time `mzern`, the MEX validation rejects with `'pzern
>   must be scalar, empty or a mpzern x 1 matrix'`; bump `mzern` and
>   force a rebuild (`rm GMI.o GMIG.o; source makegmi.sh` — make
>   does not detect `.inc` changes).
> - **Nominal save/restore expanded to FreeForm frames.**
>   `ObtainNominalSettings` / `SetToNominalSettings` now snapshot
>   and restore `pFF/xFF/yFF/zFF` and (when `nGridMat > 0`)

## Workflow notes

- The .docx generated by Acrobat from the FrameMaker PDF has
  paragraph styles named like `BodyText`, `Heading 1`, `Heading 2`.
  When inserting new content, use the same style names so the
  Table of Contents regenerates correctly.
- The PDF and DOCX have figure cross-references (e.g. "Figure 27")
  that may renumber when sections are added.  After edits, regenerate
  the TOC and figure list (Word: References → Update Table).
- The original FrameMaker source is gone (only the PDF and Acrobat-
  rebuilt DOCX remain); future updates should be made to the DOCX
  and re-exported to PDF (Word: File → Export → PDF), keeping the
  same target filename `macosMan4.0.pdf`.
- Consider migrating to a maintainable source format (Markdown +
  Pandoc, or LaTeX) for v4.1 onward.  The current Acrobat-converted
  DOCX has subtle layout artifacts and is hard to keep in sync with
  the code.
