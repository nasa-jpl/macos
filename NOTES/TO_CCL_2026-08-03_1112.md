## 1. Engine/library fix — `add_oap` off-axis geometry (the keeper)

`macos.design.Bench.add_oap` seeded the parent parabola focal length with
`f_par = r*(1 + cos θ)/2`. **This is correct only at θ = 90° folds** (cos = 0),
which is the *only* regime the OAP tests (`tBench.test_oap_relay`) and
`bench_layout` ever exercised — so the bug sat latent. The parabola polar
equation with the focus at the origin gives `r = 2f/(1 − cos θ)`, i.e.
**`f_par = r*(1 − cos θ)/2`**. Away from 90° the old form mis-placed the
parent: for a near-normal fold (AOI ~5°, θ ~170° — the DST2R regime) it demanded
r ≈ 329 m for f = 2500 and threw the vertex *behind the source* → no trace.

Fixed to `(1 − cos θ)` (90° results **bit-identical**, so `tBench` stays green,
verified). Also added:
- an **`'f'`** option to `add_oap` (specify parent focal length directly;
  conjugate derived as `r = f/cos²(AOI)`) — arbitrary fold angles now work;
- **off-axis aperture fix**: OAP `aprad` is now metadata only, no longer
  emitted as a vertex-framed `Circle`. A circular `ApVec` about the *parent
  vertex* (far from an off-axis section's beam, which is at the pole) blocks
  the whole bundle (`ok = 0`). Same frame issue as the `realize_apertures` /
  DST2R-import trap below.

Commit `02c291c`. Two render-tooling edits rode along (both general, `tBench`
green): `view_rx` labels offset perpendicular to the beam in the layout plane
(alternating sides + leaders) so they don't print on ray lines; `view_std`
now a near-square panel grid (2×2 for 4 views) so panels are ~4× larger.

New reusable analysis fn **`macos.pupil_zone_map(PUPIL_ELT, IMAGE_ELT)`**
(sibling to `macos.spot`/`macos.pupil_quality`): bins the ray grid by pupil
zone and measures each zone's image spot — the cone-from-a-pupil-patch →
detector-spot standard for pupil imaging quality.

## 2. The generic CTB example — `bench_ctb/` (development version)

`mmacos/examples/design/bench_ctb/example_ctb.m` (commit `b231c5a`, registered
in the design `README.md`). An **8-OAP, 2-DM, all-reflective coronagraph
relay** alternating pupil/focus planes:

```
source → OAP1 → DM1(stop) → DM2 → OAP2 → [focus] → OAP3 → apodizer
       → OAP4 → FPM → OAP5 → Lyot → OAP6 → field_stop → OAP7 → backend
       → OAP8 → FPA
```

- OAP focal lengths `[2500 1524 1143 1350 675 635 635 762]` mm (DST2R seeds),
  Kc = −1, near-normal folds (AOI 5°, `add_oap 'f'`+AOI, `r = f/cos²(AOI)`).
- Source = section of a sphere; `Aperture` = numerical aperture sized to fill
  the **limiting** aperture (the DM stop, not the oversized OAPs).
- **Staged per-conjugate geometric optimization** in light order, freezing
  upstream (a single WFE solve at the FPA can hide mis-collimation as defocus).
  Stage A solves **Kr-only** (a sphere — cheaper to fabricate) via a DOF switch
  on `optimize_conic`.
- Result: 3002 rays, **0 vignetting**, chief agreement 4.7e-12 mm,
  **RMS WFE 0.0014 λ** (diffraction-limited geometrically), DM1→FPA
  `pupil_zone_map` median 0.027 µm.

**Polarization is a DIAGNOSTIC, not a design axis** (Dave's call). Reported via
Al-coated mirrors → `jones_pupil`/`pol_maps` at the FPA (retardance +
diattenuation, mean vs variation). Key measured finding, which **corrected an
earlier wrong claim of mine**: in-plane fold alternation does NOT cancel fold
retardance; a naive 90°-crossed-plane (3-D) fold cuts diattenuation ~90× but
does NOT beat planar on the contrast-relevant retardance *variation* and costs
~10× WFE. Proper compensation (equal-AOI exactly-crossed pairs + astigmatism
balancing) is a **deferred** layout+optim task. We ship the planar bench.

**PIL design step** (extra Rx per lens): a pupil-imaging lens near the star
focus switches the camera from source- to pupil-imaging. Emits
`ctb_pil150.in` / `ctb_pil75.in`, reproducing Marx's DST2R trade — 150 mm vs
75 mm gives ~2.7× pupil-image size and a ~100 mm camera move (Marx: 1000/500
px, +106 mm).

## 3. Faithful DST2R reference — `bench_ctb/dst2/` (parallel)

Marx sent Brandon's original CODE V sequence
(`dst2v2_aox_v5_di_2025_05_07_fiximgtilt.seq`). Verified our CTB matches it:
OAP focal lengths **identical**, same topology, stop at dm1, 500 nm.

`cv2macos` is a CODE V macro (needs CODE V, not on this box) — but the
conversion was already done: the `DST2V2_AOX_V5_stop_at_dm1_F0{1..5}.IN`
files ARE Brandon's design converted. Brought into `dst2/` (commit `c9fcbeb`)
with `raw/` originals + `load_dst2.m` (imports, traces all 5 fields, renders).

**Two non-destructive fix-ups** the loader applies to the 2013-era cv2macos
output (raw/ untouched): (1) tighten spaced keywords (`ApType = Circle` →
`ApType=`) + add `BaseUnits`/`WaveUnits` mm, else `load_rx` fails; (2)
neutralize the OAP `ApVec` circles — cv2macos writes the CODE V off-axis
**decenter** into `ApVec` (e.g. `75 200 0`), which the engine applies about the
parent vertex → blocks all rays (same frame bug as §1; dm1 is the real stop).

All 5 fields trace 3210/3210 rays. **As-converted RMS WFE ~0.5 λ (NOT
diffraction-limited)** — reflects the converter's focus/clocking limits + a
575 nm-vs-500 nm header mismatch. Faithful *geometry* reference, not an
optimized Rx. **Plan: develop on the generic CTB; track the real instrument
here in parallel.**

## 5. NEXT STAGE — insert the diffraction part of the model (for planning)

The CTB is currently a **geometric** ray-trace model (spot sizes, RMS WFE,
pupil-zone imaging, ray-Jones polarization). The next stage is the
**diffraction / physical-optics** layer, which is what a coronagraph model
actually needs (contrast, PSF, mask propagation). Points to plan:

- **What exists to build on.** MACOS has scalar diffraction propagation
  (`macos.intensity` / `complex_field` / the COMPOSE broadband path,
  Siegman-Sziklas near-focus prop) validated against PROPER
  (`[[project_proper_validation_milestone]]`). The CTB's clean, diffraction-
  limited planar Rx is a good substrate; the DST2 reference is not (0.5 λ).
- **Coronagraph specifics needed.** FPM as an amplitude/phase mask at the
  focus (currently a passive Reference marker), Lyot stop as a real pupil
  amplitude mask, apodizer as a pupil amplitude profile — i.e. the passive
  markers become propagating masks. This is a Babinet/Lyot propagation chain,
  not just a trace.
- **Open questions for CCL/Dave.** (a) Which diffraction engine path —
  MACOS-native COMPOSE prop end-to-end, or hand off pupil fields to
  PROPER-style FFT prop between conjugates? (b) Broadband vs monochromatic
  first? (c) Does the FPM sit in the MACOS trace (needs a mask element type at
  a focus) or in an external prop step keyed off the CTB pupils?
- **Diagnostics that carry over.** `pupil_zone_map` + `jones_pupil`/`pol_maps`
  are ray-level; the diffraction stage wants a contrast metric (dark-zone
  intensity — cf. `[[project_dark_zone_geometry]]`) and PSF/Strehl from the
  complex field.
