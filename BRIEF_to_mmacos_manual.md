## The mechanics (reuse the MACOS manual's; do not invent a second pipeline)
- `docs/mmacos-manual/` with the same `Makefile`, `reference.docx`, `tools/` (the Lua filters, `number_sections.lua`,
  `figure_captions.lua`, `include_transcripts.lua`), `src/NN_*.md` sections, `src/transcripts/` generated, `src/media/`.
  Copy the tooling by reference (a Makefile variable pointing at `../macos-manual/tools`), not by duplication.
- **Generated, never typed**: each chapter's listings and figures come from running the stage script under a
  journal-like driver -- a MATLAB `-batch` run whose stdout and saved figures land in `src/transcripts/` and
  `src/media/` by marker (`<!-- transcript: NAME -->`), regenerated by `make transcripts`.  Write the driver
  (`tools/regen_mmacos_transcripts.py` + per-chapter `tools/transcripts/<name>.m`) BEFORE the prose: a chapter with
  no generated artefact is not started.  Pin every quoted number by the cross-architecture rule (5 figures on a
  signal, a bound on a numerical zero) so CCMac can gate the manual on the Mac the way he gates the engine.
- **Three voices per chapter**, in this order: *You ask* (the prompt a user gives the assistant, verbatim, short);
  *The assistant reads* (the exact files: the CLAUDE.md, the optical_design rule, the notes topic -- as a list of
  paths, so a reader can hand them to any assistant); *It runs* (the template or runner, the generated transcript,
  the figure, the number).  Product names per the convention: MACOS, SMACOS in capitals, *mmacos* and *pymacos* in
  italics in prose.
- Chapter 1 first (Telescope), then 2 (instruments and benches via Bench), then 3-7 in the plan's order.  Each chapter
  is one commit with its driver, its generated artefacts and its prose; the manual builds (`make all pdf`) at every
  commit.  No edit copies yet (Dave has not edited); when he returns the `edits/` flow starts as for the MACOS manual.
- The Part II page template: write it once (what it is, the knobs, the figure, the number, the prompt) and generate
